# งาน (Tasks)

## 1. Schema และ domain

- 1.1 เพิ่ม `voided` และ `finished` ใน `item_status` และตาราง `order_item_events` พร้อม enum ของผู้กระทำและ index (D1, D2); ตรวจว่า migration ที่ generate ใช้กับฐานข้อมูลทดสอบได้ และแถวเดิมไม่เปลี่ยน
- 1.2 ปรับ `lib/domain.ts`: สถานะ, `void → voided` ที่ต้องมีเหตุผล, หมายเหตุแบบไม่บังคับสำหรับการตัดสินคำขอยกเลิก, `RESOLVED`, `CHARGED`, การแปลงชื่อสถานะฝั่งลูกค้า, กฎของเหตุผล (D3); ตรวจด้วย unit test ทุกการเปลี่ยนสถานะที่อนุญาตและที่ถูกปฏิเสธ ความยาวเหตุผล (" ", "ok", "abc", 501 ตัวอักษร) ยอดรวมบิลที่นับเฉพาะ `served` และ `finished` และชื่อสถานะ

## 2. ชั้น service

- 2.1 ทำ `transitionItems()` พร้อมการล็อกแถว ตรวจโต๊ะเดียวกันและสถานะเดียวกัน error 404/400/409 ใช้เวลาเดียว และบันทึก event (D4); ให้เส้นทางเปลี่ยนสถานะทีละจานของลูกค้าและพนักงานใช้ฟังก์ชันนี้; ตรวจด้วย test: กลุ่มสองจานใช้ `at` เดียวกัน, ต่างโต๊ะ → 400, ต่างสถานะ → 400, จานที่เปลี่ยนไประหว่างนั้น → 409 ระบุจานนั้นและไม่มีอะไรเปลี่ยน, void ไม่มีเหตุผล → 400, ยืนยันยกเลิกพร้อมหมายเหตุบันทึกหมายเหตุไว้
- 2.2 บันทึก `none → pending` ตอนยืนยันตะกร้า (D6) และตั้งสถานะสุดท้ายพร้อม event ของระบบเมื่อจ่ายเงิน Mark paid และเคลียร์โต๊ะ (D5); ตรวจด้วย test: บิลที่จ่ายแล้วเปลี่ยน served เป็น finished และคง cancelled, การเคลียร์โต๊ะ void รายการ pending/in-progress ด้วย "table cleared", ยอดรวมบิลไม่เปลี่ยนหลังปิด, เงื่อนไขการจ่ายรับ voided
- 2.3 Query telemetry สำหรับจำนวนต่อเมนูและ timeline รายจาน พร้อมกฎช่วงวันที่และขอบเขตสาขา (D7); ตรวจด้วย test: จำนวนต่อเมนูในสถานการณ์ที่รู้ผล, ข้อมูล ASOK ไม่ปนใน SIAM, `from > to` และวันที่ผิดรูปแบบถูกปฏิเสธ, event ใน timeline เรียงตามเวลาพร้อมผู้กระทำและโน้ต

## 3. API

- 3.1 `POST /api/console/[branch]/items/batch`; route ทีละจานส่งต่อไปยัง service เดียวกันพร้อมโน้ตแบบไม่บังคับ (D4, D8); ตรวจด้วย test: 401 เมื่อไม่มี session, 403 สาขาอื่น, ผลลัพธ์ของ batch ตามข้อ 2.1
- 3.2 `GET /api/console/[branch]/telemetry/dishes` และ `/telemetry/items` (D7); ตรวจด้วย test: 401, 403, 400 เมื่อช่วงวันที่หรือ menu item ID ผิด, รูปแบบและค่าของ JSON

## 4. UI

- 4.1 คอนโซล: กล่องถามเหตุผล/หมายเหตุสำหรับการกระทำทีละจาน ชื่อสถานะ voided และเหตุผลในแผงด้านข้าง บอร์ดซ่อน voided (D8); ตรวจใน browser walkthrough ว่า void โดยไม่มีเหตุผลถูกบล็อก และเหตุผลแสดงในแผงด้านข้าง
- 4.2 คอนโซล: การเลือกแบบกลุ่มจำกัดโต๊ะและสถานะเดียวกัน เลือกทั้งหมด แถบปุ่มติดด้านล่าง บนบอร์ด แผงด้านข้าง และรายการบนโทรศัพท์ (D8); ตรวจใน walkthrough: เริ่มทำอาหาร pending สองจานพร้อมกัน checkbox ของโต๊ะอื่นถูกปิด และ void แบบกลุ่มด้วยเหตุผลเดียว
- 4.3 ลูกค้า: voided และ cancelled แสดงเป็น "Cancelled" ทั้งคู่โดยไม่มีเหตุผล; ตรวจใน walkthrough
- 4.4 Polling ทุก 10 วินาที และการหยุด/กลับมาอัปเดตของลูกค้า (D9); ตรวจด้วย unit test ของกฎการหยุด และใน walkthrough ว่าโทรศัพท์ที่ไม่มีการใช้งานหลังจ่ายเงินไม่ส่ง request เลย 25 วินาที และกลับมาอัปเดตเมื่อมีการแตะหน้าจอ
- 4.5 Walkthrough: ลิงก์เดิม `/t/5` คาดหวังหน้า not-found มาตรฐานแทน "Table not found" (delta ของ menu-browsing); ตรวจว่าขั้นตอนใน walkthrough ตรวจหน้า 404 และไม่มีเมนู
