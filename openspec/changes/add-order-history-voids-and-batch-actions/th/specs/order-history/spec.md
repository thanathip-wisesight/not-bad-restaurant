# Spec Delta

## Purpose

เก็บบันทึกพร้อมเวลาของทุกการเปลี่ยนสถานะของอาหาร และเปิดให้ดูเป็น JSON แยกตามสาขา เพื่อให้ร้านเห็นว่าเมนูไหนขายดี และเมนูไหนถูกยกเลิกหรือถูก void บ่อย

## ADDED Requirements

### Requirement: บันทึกการเปลี่ยนสถานะ (Status change log)
ทุกการเปลี่ยนสถานะของ OrderItem SHALL ถูกบันทึกพร้อมสถานะก่อนหน้า (ไม่มี เมื่ออาหารถูกยืนยันครั้งแรกเป็น `pending`) สถานะใหม่ เวลา ผู้ทำ (พนักงาน อุปกรณ์ของลูกค้า หรือระบบ) และเหตุผลหรือหมายเหตุ (ถ้ามี) บันทึก SHALL ถูกเก็บไว้หลังบิลปิด และ SHALL ไม่ถูกแก้ไขหรือลบโดยแอปพลิเคชัน การเปลี่ยนแปลงที่ทำพร้อมกันในกลุ่มเดียว SHALL ใช้เวลาเดียวกัน

#### Scenario: Timeline เต็มของอาหารที่เสิร์ฟแล้ว
- **WHEN** อาหารถูกยืนยันเวลา 12:00:00 เริ่มทำเวลา 12:01:00 เสิร์ฟเวลา 12:07:00 และบิลถูกจ่ายเวลา 12:30:00
- **THEN** บันทึกของอาหารคือ: ไม่มี→`pending` 12:00:00 (ลูกค้า), `pending`→`in_progress` 12:01:00 (พนักงาน), `in_progress`→`served` 12:07:00 (พนักงาน), `served`→`finished` 12:30:00 (ระบบ)

#### Scenario: เก็บเหตุผลของ void
- **WHEN** พนักงาน void อาหารด้วยเหตุผล "burnt"
- **THEN** บันทึกของการเปลี่ยนแปลงนั้นเก็บ "burnt" และพนักงานผู้ทำ

### Requirement: API จำนวนต่อเมนู (Dish counts API)
คอนโซล SHALL มี JSON endpoint ที่คืนค่า สำหรับสาขาที่เลือกและช่วงวันที่ (ไม่บังคับ) หนึ่งรายการต่อ menu item ID พร้อมชื่ออาหาร และจำนวนจานที่ถูกสั่ง, `finished`, `cancelled` และ `voided`

#### Scenario: จำนวนต่อเมนู
- **WHEN** ในช่วงนั้น SIAM มีผัดไทยถูกสั่ง 3 จาน ในจำนวนนี้ finished 2 จาน และถูก void 1 จาน
- **THEN** รายการผัดไทยแสดง ordered 3, finished 2, cancelled 0, voided 1

#### Scenario: แยกตามสาขา
- **WHEN** ASOK มีผัดไทยถูกสั่ง 5 จานในช่วงเดียวกัน
- **THEN** จำนวนของ SIAM ไม่รวมจานเหล่านั้น

### Requirement: API timeline รายจาน (Dish timeline API)
คอนโซล SHALL มี JSON endpoint ที่คืนค่า สำหรับสาขาที่เลือก ช่วงวันที่และ menu item ID (ไม่บังคับ) อาหารแต่ละจานพร้อมเลขบิล โต๊ะ สถานะปัจจุบัน และบันทึกการเปลี่ยนสถานะทั้งหมดเรียงตามเวลา

#### Scenario: กรองตามเมนู
- **WHEN** พนักงานขอ timeline ของ SIAM สำหรับ menu item ID ของผัดไทย
- **THEN** ได้เฉพาะผัดไทยของ SIAM แต่ละจานพร้อมบันทึกของมัน

### Requirement: การเข้าถึง telemetry (Telemetry access)
Telemetry endpoint SHALL ใช้กฎการเข้าถึงคอนโซล: status 401 เมื่อไม่มี staff session, 403 สำหรับสาขาที่ผู้ใช้ไม่ได้สังกัด และช่วงวันที่หรือ menu item ID ที่ไม่ถูกต้อง SHALL ถูกปฏิเสธด้วย status 400

#### Scenario: สาขาที่ไม่ได้สังกัด
- **WHEN** `siam.staff` ขอจำนวนต่อเมนูของ ASOK
- **THEN** ได้ status 403

#### Scenario: ช่วงวันที่ผิด
- **WHEN** request มี `from` ช้ากว่า `to`
- **THEN** ได้ status 400
