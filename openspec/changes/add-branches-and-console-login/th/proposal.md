# ข้อเสนอการเปลี่ยนแปลง (Proposal)

## เหตุผล (Why)

แบรนด์มีร้านมากกว่าหนึ่งสาขา หมายเลขโต๊ะเพียงอย่างเดียวจึงไม่สามารถระบุโต๊ะได้อีกต่อไป และใครก็ตามที่รู้ URL ก็เข้าหน้าคอนโซลของร้านได้ ระยะที่ 2 (`rough-spec-phase-2.md`) ผูก QR code ของทุกโต๊ะเข้ากับสาขา และกำหนดให้คอนโซลต้องเข้าสู่ระบบโดยพนักงาน โดยจำกัดขอบเขตตามสาขาที่พนักงานแต่ละคนสังกัด การเปลี่ยนแปลงนี้ยกเลิก non-goal "ไม่มีการยืนยันตัวตน" ของระยะที่ 1 บางส่วน เฉพาะฝั่งคอนโซลเท่านั้น

## สิ่งที่เปลี่ยน (What Changes)

- **BREAKING** URL ของโต๊ะเปลี่ยนเป็น `/b/<branchCode>/t/<tableNo>` (เช่น `/b/SIAM/t/5`) ส่วน path เดิม `/t/<tableNo>` จะแสดง "table not found"
- เพิ่มสาขา (รหัส + ชื่อ) แต่ละสาขามีโต๊ะของตัวเองโดยเริ่มนับเลขจาก 1 ส่วนเมนูและราคายังใช้ร่วมกันทั้งแบรนด์ ข้อมูลตั้งต้น (seed): SIAM (10 โต๊ะ) และ ASOK (6 โต๊ะ)
- ตะกร้า ออร์เดอร์ บิล และประวัติบิล สังกัดสาขาผ่านโต๊ะของมัน โต๊ะเลขเดียวกันในสองสาขาจะไม่ใช้ session ร่วมกันเด็ดขาด
- **BREAKING** เลขบิลเพิ่มรหัสสาขา: `SIAM-T05-0042` (ใช้ลำดับเลข sequence เดียวทั้งระบบ)
- โต๊ะ ตะกร้า ออร์เดอร์ และประวัติบิลที่มีอยู่เดิม ถูกย้ายไปอยู่สาขา SIAM โดยเลขบิลที่ออกไปแล้วคงไว้ตามเดิม
- พนักงานเข้าสู่ระบบด้วย username และ password โดย session cookie จะคงสถานะล็อกอินไว้จนกว่าจะไม่มีการใช้งาน 24 ชั่วโมง หรือจนกว่าจะออกจากระบบ
- ทุกหน้าใต้ `/console` (บอร์ด ประวัติ พิมพ์) และทุก console API ต้องเข้าสู่ระบบ ผู้ใช้ที่สังกัดสาขาเดียวจะเข้าคอนโซลของสาขานั้นทันที ผู้ใช้ที่สังกัดหลายสาขาต้องเลือกสาขาและสลับได้ภายหลัง ทุกการอ่านและการกระทำในคอนโซลจำกัดเฉพาะสาขาที่เลือก โดยตรวจสอบที่ฝั่งเซิร์ฟเวอร์
- บัญชีพนักงานมาจาก seed เท่านั้น (`siam.staff`: SIAM; `area.manager`: SIAM และ ASOK) มีโหมด seed แบบไม่ลบข้อมูล `--users-only` ที่เพิ่มสาขาและบัญชีพนักงานลงในฐานข้อมูลเดิมโดยไม่แตะประวัติ ฝั่งลูกค้ายังเปิดใช้ได้โดยไม่ต้องเข้าสู่ระบบ

### สิ่งที่ไม่ทำ (Non-goals)

- การสมัครสมาชิก หน้าจัดการผู้ใช้หรือสาขา การรีเซ็ตหรือเปลี่ยนรหัสผ่าน บทบาท/สิทธิ์อื่นนอกจากการสังกัดสาขา
- การจำกัดอัตราการเรียก (rate limiting) การล็อกบัญชี CSRF token นอกเหนือจาก cookie แบบ `SameSite=Lax` audit log และกฎความแข็งแรงของรหัสผ่าน
- เมนูหรือราคาแยกตามสาขา และรูปแบบใบเสร็จแยกตามสาขา

## ความสามารถ (Capabilities)

### ความสามารถใหม่

- `restaurant-branches`: ตัวตนของสาขา โต๊ะแยกตามสาขา เมนูร่วม การแยก session และบิลตามสาขา และการย้ายข้อมูลเดิมไปสาขา SIAM
- `console-access`: การเข้า/ออกจากระบบของพนักงาน อายุของ session การป้องกันคอนโซลและ API การสังกัดสาขา การเลือกและสลับสาขา และการอนุญาตตามขอบเขตสาขา

### ความสามารถที่แก้ไข

- `menu-browsing`: การเข้าเมนูด้วย URL จาก QR ของโต๊ะ ตอนนี้มีรหัสสาขาและแสดงชื่อสาขา
- `payment`: รูปแบบเลขบิลมีรหัสสาขา และปรับตัวอย่างการจ่ายที่แคชเชียร์
- `restaurant-console`: ภาพรวมโต๊ะ แถบโต๊ะ (Table strip) การ Mark Bill paid ประวัติบิล และการพิมพ์ใบเสร็จ จำกัดเฉพาะสาขาที่เลือก และใบเสร็จแสดงชื่อสาขา

## ผลกระทบ (Impact)

- Schema: เพิ่ม `branches`, `users`, `user_branches`, `staff_sessions`; เพิ่ม `tables.branch_id` พร้อม unique (branch, number); migration พร้อมเติมข้อมูลเดิมเป็นสาขา SIAM
- Routes: หน้าและ API ฝั่งลูกค้าย้ายไปอยู่ใต้ `/b/[branch]/…`; หน้าคอนโซลอยู่ใต้ `/console/[branch]/…` และมีหน้าใหม่ `/login`; console API อยู่ใต้ `/api/console/[branch]/…`; เพิ่ม `/api/auth/login` และ `/api/auth/logout`
- `lib/service.ts` เพิ่มการค้นหาที่รู้จักสาขาและการตรวจสอบความเป็นเจ้าของตามสาขา; เพิ่ม `lib/auth.ts` (แฮชด้วย scrypt และจัดการ session) โดยใช้เพียง `crypto` ที่มากับ Node
- ปรับ seed, README (ข้อมูลบัญชีทดลอง), ลิงก์ในหน้า demo index, unit test และ browser walkthrough ไม่มี dependency ใหม่
